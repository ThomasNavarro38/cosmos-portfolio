## Intent

**Problem:** The Colophon's two `<pre>`s print `career.json` and `layout.generated.json` with no treatment at all. They have no accessible name, no syntax setting, no `surface-raised` block, no scroll container and no monospace. The evidence is technically on the page, but it is not set as DESIGN.md §7.11 `components.colophon-json` requires.

**Approach:** Each file is still drawn verbatim and in full in its own `<pre>`, but its text is split into luminance-set runs by a pure, import-free lexer: keys, scalar values, and everything else (structure). The `<pre>` becomes a named, keyboard-scrollable region on `surface-raised` with a 1px `surface-edge` left border, set in a new `--font-mono` token (the system monospace stack). That token is used here and nowhere else.

## Boundaries & Constraints

**Always:**
- **Every byte, in order.** The text content of each `<pre>` equals its fetched file exactly. The runs' concatenation is the input, for any input string, whether or not it is valid JSON. Nothing is trimmed, reformatted, parsed and re-stringified, summarised or folded. There is no `max-height`, `height`, `overflow-y`, `<details>` or "show more".
- **Luminance only** (`components.colophon-json`): key runs at `ink-lift-dark`, scalar value runs (strings that are not keys, numbers, `true`, `false`, `null`) at `ink-prose-dark`, and everything else (`{}[]:,`, whitespace, anything unrecognised) at the `<pre>`'s own `ink-label-dark`. No hue. A key is a string run whose next non-whitespace character is `:`.
- **Markup:** `<pre className="colophon-exhibit" role="region" aria-label={name} tabIndex={0}>`. Key runs are `<span className="colophon-json-key">`, value runs are `<span className="colophon-json-value">`, and structure runs are bare text. `name` is the file's name read off `EXHIBIT_PATHS` (`career.json`, `layout.generated.json`), so no file name is authored twice. The order stays career `<pre>`, derivation table, layout `<pre>`.
- **Treatment** (`colophon.css`, token custom properties only): `background: var(--color-surface-raised-dark)`, `border-left: 1px solid var(--color-surface-edge-dark)`, `color: var(--color-ink-label-dark)`, `font-family: var(--font-mono)`, size, weight, line-height and letter-spacing from the `field-value` role, `margin: 0`, `padding: var(--space-md) var(--space-lg)`, `overflow-x: auto`. The text runs to its natural width with no wrapping, and the page itself never scrolls sideways. `:focus-visible` draws `outline: 1px solid var(--color-stroke-focus-dark); outline-offset: 3px`, with a `forced-colors` `CanvasText` outline as `chart.css` has. No radius, no shadow.
- **The family token:** DESIGN.md frontmatter gains `typography.fontFamily.mono: 'ui-monospace, SFMono-Regular, Menlo, Consolas, "Liberation Mono", monospace'`, regenerated by `npm run tokens`. §3's "There is no second family at M2" gains a clause naming the Colophon's JSON body as the one exception (§7.11). The 12px/1.7 assumption is not adopted: the component block's ratified `typography: {typography.field-value}` holds.
- **Monospace nowhere else:** `--font-mono` appears in exactly one rule (`.colophon-exhibit`), and the word `monospace` appears in no shipped file under `src/` outside `src/tokens/`. No shipped `.tsx` draws `<code>`, `<kbd>`, `<samp>` or `<tt>`, and `<pre>` appears only in `colophon.tsx`. Each of these is held by an audit with mutation rows.
- `src/colophon/` still imports nothing from `src/data/`, `generated/` or `src/derive/`. The lexer imports nothing.

**Block If:** the token generator rejects a `mono` family key, so the family cannot be a token.

**Never:**
- No visible new copy: no heading, caption or label naming the files (5.4 owns prose), and no download link.
- No hue, no syntax-highlighting library, no `JSON.parse`/`JSON.stringify` in the lexer, and no change to `derivations.ts`, `exhibits.ts`, `src/derive/`, the artifact or `career.json`.
- No 5.4 absences prose and no 5.5 re-solve.

## I/O & Edge-Case Matrix

| Scenario | Input / State | Expected Output / Behavior | Error Handling |
|----------|--------------|---------------------------|----------------|
| Real files | the fetched texts | each `<pre>` reads back byte-identical. Its key spans are, as a multiset, the files' keys and its value spans the scalar leaves | — |
| Escapes in a string | `{"a\"b": "c\\"}` | the key run is `"a\"b"` and the value run is `"c\\"`, unsplit | — |
| Key with space before colon | `{"k" : 1}` | `"k"` is a key | — |
| String as a value | `["k", 1]` | `"k"` is a value, not a key | — |
| Not JSON | `oops {` or an unterminated `"abc` | runs concatenate to the input. The unterminated string runs to the end as one value run | no throw |
| Empty text | `''` | no runs; the `<pre>` is empty | — |
| No exhibits | `null` | `<h1>` alone | — |

## Design Notes

**Why a region.** A `<pre>` maps to the generic role, and ARIA 1.2 prohibits naming a generic element, so `aria-label` on a bare `<pre>` is dropped by some readers and flagged by axe. A horizontally scrollable box must also be keyboard-reachable (WCAG 2.1.1, axe `scrollable-region-focusable`). `role="region"` together with `aria-label` and `tabIndex={0}` is the standard way to name a scrollable container. It also gives each file a landmark a screen-reader user can jump to.

**Why the file name.** It is the one name already on the site (`EXHIBIT_PATHS`), it is checkable against the URL, and it is not new copy. A visible label would be new copy, and 5.4 owns the page's prose.

**Why a lexer, not `JSON.parse`.** Parsing and re-stringifying would show the visitor a reformatted file, not the bytes. The lexer only marks spans over the original text, so "every byte the scene reads" holds by construction: it is the concatenation test.
