### Diff-scope review (`bmad-review`: adversarial, edge-case-hunter, verification-gap over `src/` in `a464343..fa581dc`)

**F-1 — Release, then focus another Project during the slide-out, and the camera cuts.** CONFIRMED (edge-case). Boundary: 2.7 ↔ 2.8.
- In `render-scene/focus-model.ts:242-246`, `null → B` while the release slide is still running goes through `flipSlide`. That shortens the ease by the reversing factor, as if returning to the pose just left. But the goal is B's pose.
- The lens probe with B 95 units away, 3 frames after the release: the camera covered the distance in 1 frame (`seconds = 0.0027`).
- This violates FR-17 / UX-DR28 ("it does not jump; it flies"), and reduced motion included.
- It is unreachable on committed data (one Project) and reachable as soon as two exist.
- **Fix now.** Only shorten when the reopened ID is the one the slide closed from; otherwise run full length.

**F-2 — A mid-slide release leaves the off-screen panel visible to AT and in the tab order.** CONFIRMED. All three lenses found it independently. Boundary: 2.7 ↔ 2.10.
- In `shell/panel-model.ts:388`, the close delay is always `FOCUS_SECONDS × pace`. The browser shortens the reversed *transform* transition, but the visibility transition is fresh and never shortened.
- So for up to `(1−factor) × 0.8 s` the panel sits at `translateX(100%)` with `visibility: visible`, and its release button is tabbable.
- This contradicts the module's own claim "hidden exactly once it ends" (`panel-model.ts:357-360`).
- No test pairs the panel's delay with `flipSlide` (`panel-model.test.ts:217-225`, `:291-298` cover the uninterrupted slide only).
- **Fix now.**

**F-3 — Keyboard listeners outlive the scene.** CONFIRMED (adversarial + verification-gap). Boundary: 2.3 ↔ 2.9 ↔ 2.10.
- The `window` `keydown` listener is registered in `SceneHost` outside `SceneBoundary` (`scene-host.tsx:191-238`, `:252-259`). When the scene chunk fails, `buildScene` throws, or WebGL is absent, the boundary renders `null` but ↑/↓/Home are still `preventDefault`-ed and written to the store.
- So in the "index alone" state the header calls legitimate (`scene-host.tsx:27-28`), keyboard users lose native page scrolling.
- **Fix now.** It is small, and it is reachable today for any visitor without WebGL until 4.1.

**F-4 — Clamped frame delta vs wall-clock CSS.** CONFIRMED in code, PLAUSIBLE in effect (adversarial). Boundary: 2.5 ↔ 2.7 ↔ 2.8.
- `stepFocus` / `flightFrame` / Mote blend advance by `dt` clamped to `RAIL_MAX_FRAME_SECONDS` = 0.1 s (`focus-model.ts:248`). The panel's CSS slide and the WAAPI cross-fade run on wall time.
- Below 10 fps the "one move" halves diverge. The lens probe at 200 ms frames: camera 1.6 s against panel 0.8 s, and a reversed release of 0.057 s against 0.4 s.
- **Defer** to the M1 tuning pass on target hardware (6.4 owns first-paint hardware).

**F-5 — Travelled release with a mouse on Safari / macOS Firefox drops DOM focus to `<body>`.** PLAUSIBLE (adversarial).
- `focusMove` returns `null` for a travelled release (`panel-model.ts:212-220`). The assumption is that DOM focus already sits on the door clicked, but those browsers do not focus a `<button>` on click.
- DOM focus stays in the panel container, which then hides.
- Not run on Safari. **Defer**, and verify it in 6.5's launch pass.
- Guard: move focus only if `document.activeElement` is inside the panel.

**F-6 — Under reduced motion a blocked Mote label is hidden for the entire Focus.** PLAUSIBLE (adversarial). Boundary: 2.8 ↔ 2.10.
- The frozen orbit clock (`mote-model.ts:503`) removes the turning that the 2.8 deferral relied on to unblock labels (`mote-model.ts:648`, `deferred-work.md:586`).
- **Defer to 3.5**, but add a reduced-motion case to its ACs.

**F-7 — Wheel inertia crosses a mode flip.** PLAUSIBLE (adversarial).
- Trackpad momentum after `Escape` turns into Rail travel, because `wheelIntent` reads the store per event (`scene-host.tsx:195-209`, `rail-input.ts:126-140`). The Rail then does not resume "where it was left" (AC 2.9, `epics.md:1064`).
- **Defer** to M1 feel-testing. A pure settle-window rule in `rail-input.ts` if it reads.

**F-8 — Free flight and its target are not exposed to AT.** CONFIRMED (adversarial).
- There is no `aria-current` on the flown-to Client or `overview`, and no announcement on mode change (`index-nav.tsx:106-116`). This extends the `railPosition` a11y deferral (`deferred-work.md:369`) to free flight.
- Also, the `↩` glyph sits inside the button's accessible name (`index-nav.tsx:108`).
- **Defer to 3.8** (stateful instruction slot).

**F-9 — Doc drift across story boundaries.** CONFIRMED (adversarial).
- `focus-model.ts:22-31` and `render-scene/README.md:18,101` still say the release goal is "the live Rail pose". Since 2.9 it is `flightFrame`'s pose.
- `scene-host.tsx:219`, `rail-input.ts:160-162` and `shell/README.md:81` describe Home as "`enterRail()` then the opening frame", while it is the `goHome` door, which releases Focus first (2.10).
- **Fix now** (docs). A maintainer following them could break the `mode === focusOrigin` invariant.

**F-10 — No `End` counterpart to `Home`.** CONFIRMED (adversarial). It is not required by AC 2.9 (`epics.md:1059-1060`) (`rail-input.ts:178-186`). **Accept** for Epic 2, and note it for the 3.8 instruction slot.
