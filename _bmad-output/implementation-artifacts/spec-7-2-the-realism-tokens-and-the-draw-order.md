## Intent

**Problem:** The realism layer needs a hued colour source and two new draw orders, and today the achromatic audit rejects any hue, the glow scan rejects the word `glow`, and the draw order is split across three modules. If 7.6 and 7.7 each settled this themselves, hue would have no single audited home and units could disagree on what draws over what.

**Approach:** Declare the `realism-*` tokens in DESIGN.md's frontmatter and the five render orders in `scene-model.ts`, change the audits only by their named allowances, and add a scan that keeps `realism-*` references inside `realism/`. Nothing draws with any of it yet.

## Boundaries & Constraints

**Always:**
- `DUST 1`, `BODY 2` and `MOON 3` keep their values, and `dust-model.ts` and `notable-model.ts` keep exporting their constant, so every importer and every existing audit of those imports still holds.
- Each audit exemption is exact: the achromatic audit by the key prefix `realism-`, the glow scan by the one identifier `GLOW_RENDER_ORDER` in the one file `src/render-scene/scene-model.ts`. Each comes with a mutation row proving the near miss still fails.
- The token values are starting values, tuned by Thomas's on-screen judgement in Epic 8. Nothing here claims how they look.

**Block If:**

- A test can only pass by changing an audit beyond the named allowances (AD-19). HALT `blocked` with condition `audit change outside AD-19's allowances`.

**Never:**
- Change `scripts/tokens.ts` or `scripts/tokens.test.ts`'s existing rows.
- Mount, import or read a realism token or `GLOW_RENDER_ORDER`/`FILL_RENDER_ORDER` from any drawing code (7.6, 7.7).

## Design Notes

**Values.** Bare and `-dark` carry the same hex, so a placeholder cannot be mistaken for a designed light theme:

```yaml
realism-star-glow: "#B09468"
realism-star-glow-dark: "#B09468"
realism-ambient-floor: "#0E1626"
realism-ambient-floor-dark: "#0E1626"
```

The glow's relative luminance (about 0.31) is under `stroke-active` (about 0.47), but the ceiling itself is pinned in 7.7, against what the shader outputs.

**Reach pattern.** On comments-blanked source, `/--(?:color-)?realism-|['"`]realism-/`. The quote anchor is what separates a token key from `'./realism-mount.tsx'`, and it also catches a key built from a `'realism-'` prefix. A property name assembled wholly at runtime, like `` `--color-${x}` ``, stays out of reach, and the test's comment says so. The path exemption is `render-scene/realism/` with the slash, so `render-scene/realism-mount.tsx` is still scanned.

**Glow allowance.** Inside `effectsIn`, and only for `src/render-scene/scene-model.ts`, blank `\bGLOW_RENDER_ORDER\b` before matching. 7.7 adds `realism/` to this same place.

**Known limit.** `auditPaint` in `scripts/preview.test.ts` now admits a realism hex in the preview's SVG. Tightening it is an audit change outside AD-19's list, so this story leaves it. The reach audit stops `scripts/preview.ts` naming a realism token and `scripts/preview.test.ts:285` fails a hex literal there, so what stays uncovered is a key or hex assembled wholly at runtime.

**Pixel check.** Serve each build with `npx vite preview --outDir <dir>` and capture through chrome-devtools with reduced motion emulated and a settle wait. Capture the baseline twice first: if it differs from itself, record that and compare over the static regions, saying so. The record goes in this spec's Auto Run Result.
