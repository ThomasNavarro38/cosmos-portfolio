# src/tokens/

Design tokens generated from the YAML frontmatter of `_bmad-output/planning-artifacts/ux-designs/ux-cosmos-portfolio-2026-09-01/DESIGN.md` (AD-12). One source for colour, type, spacing, radius and stroke-weight values shared by both rendering surfaces, so the scene and the DOM cannot drift apart visually. DESIGN.md carries no motion values, and none are emitted here: timing constants stay in `src/shell/`.

**Imports:** nothing. Tokens are leaves.
**Imported by:** `src/shell/`, `src/render-scene/`, `src/render-fallback/`, `src/colophon/`, and the tooling in `scripts/` (`scripts/tokens.test.ts` reads `tokens.ts` to check the acceptance values). Never by `src/derive/` — derivation is pure and knows nothing of appearance. The direction is one-way: `scripts/` imports `src/derive/boundaries.ts` (the comment stripper and import scanner) and `src/tokens/`, and nothing under `src/` imports `scripts/`.

## Never hand-edit

Both files are generated by `scripts/tokens.ts` and committed. Change DESIGN.md's frontmatter, then run `npm run tokens`. `npm run gate` (and so `npm run build`) fails when either file differs by one byte from a fresh generation or has lost its banner on line one. The generator lives outside `src/` because it reads and writes files, and this directory may import nothing.

Because this directory is exempt from the literal-colour scan, the gate also fails if it holds any file other than `README.md`, `tokens.css` and `tokens.ts`. The same gate fails when any code, stylesheet or markup under `src/` (outside this directory, tests, and dot-files and dot-directories), the root `index.html`, or every governed file under `public/` (scripts, stylesheets, `.html`, `.svg` — the same classification as `src/`) writes a literal colour — `#hex`; `rgb(`, `rgba(`, `hsl(`, `hsla(`, `hwb(`, `lab(`, `lch(`, `oklab(`, `oklch(`, `color(`; a CSS named colour as a value or a whole string; a system colour where it is paint (a CSS value, a markup paint attribute such as `fill`, a script string under a colour-shaped key — never `createElement('canvas')` or `id="canvas"`) outside `@media (forced-colors: active)` or `(forced-colors)`; or a `0x` number handed to `Color(`, a colour-named receiver's `.set(`, `.setHex(`, `.setRGB(` or a colour key (3.9) — naming `file:line`. Decimal and float colours (`Color(16777215)`, `Color(1, 1, 1)`, `setHSL`) and CSS written inside a multi-word script string are known blind spots, listed in `scripts/colour-literals.ts`. `transparent`, `currentColor` and `color-mix(` stay legal. Read the colour from here instead.

## Files

| File | Role |
| --- | --- |
| `tokens.css` | CSS custom properties on `:root`, for the DOM: `--color-<key>`, `--font-<key>`, `--type-<role>-{font-family,font-size,font-weight,line-height,letter-spacing}`, `--space-<key>`, `--radius-<key>`, `--stroke-<key>`. Imported once, by `src/main.tsx`, so every DOM stylesheet (first `src/shell/focus-panel.css`, 3.6) reads the same values. |
| `tokens.ts` | The same values as one `as const` object (`tokens`), for code that cannot read a custom property — scene materials above all. Literal types, `{group.key}` aliases resolved. |

## What is emitted

Only what DESIGN.md states: `colors` (every bare/`-dark` pair — bare is the future light theme, `-dark` the shipped M2 value), `typography` (the font families and the eleven ramp roles), `spacing`, `rounded`, and `components.stroke-weight`. The other `components.*` blocks are parsed but applied by the stories that draw them. Generation fails loudly, naming the key, on an unresolvable alias, a colour without its pair, a missing ramp role or field, a spacing value of 16px or 24px, or a YAML construct outside the supported subset.
