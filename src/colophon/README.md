# src/colophon/

The how-it-was-made surface: shows raw authored input, the mapping rules, and the derived result side by side, and lazily loads the solver so a visitor can re-run it live.

**Imports:** `src/tokens/`; within the directory, `colophon.tsx` imports React, `./exhibits.ts`, `./derivations.ts` and `./colophon.css` only, and `exhibits.ts` and `derivations.ts` import nothing (held by the maintenance suite). Never `generated/` and never `src/data/`: both files it exhibits reach it as emitted data (AD-17), published byte for byte by `scripts/exhibits.ts` at `/career.json` and `/layout.generated.json` and fetched at runtime. May reach `src/derive/` **only** through a dynamic import for the live re-run — never a static import, which would hoist the solver onto the entry path.
**Imported by:** `src/shell/` via dynamic import only.

## Files

| File | Role |
| --- | --- |
| `colophon.tsx` | The `/colophon` route's surface (4.2, 5.1, 5.2), default-exported for `lazy()`. The default `Colophon`'s one effect is `startExhibits(fetch, setExhibits, logged)`, run once, its stop — which aborts the requests — the cleanup (no state update after it; audited in `colophon.test.ts`); a failed fetch is logged once with `console.error` and draws nothing more, an abort is silent, and there is no loading indicator and no retry. `ColophonPage({ exhibits })` draws `<h1>the model</h1>` and, once the files have arrived, each one's text verbatim in its own `<pre>`, career first — unset in 5.1 (no name, no measure, no syntax setting; 5.3 owns them). Imports React, `exhibits.ts`, `derivations.ts` and `colophon.css` only — not the shell, not the motion preference.
