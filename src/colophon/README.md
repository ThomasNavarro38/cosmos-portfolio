# src/colophon/

The how-it-was-made surface: shows raw authored input, the mapping rules, and the derived result side by side, and lazily loads the solver so a visitor can re-run it live.

**Imports:** `src/tokens/`; within the directory, `colophon.tsx` imports React, `./exhibits.ts`, `./derivations.ts`, `./json-setting.ts`, `./absences.ts`, `./live-solve.ts` and `./colophon.css`, the shell's identity words `../shell/chrome-model.ts` (`IDENTITY_NAME`, `IDENTITY_MODEL`, Epic 5 item 38) and its shared contact route `../shell/contact-route.tsx` (6.3) — both in the `ui` chunk, so the colophon chunk still holds `src/colophon/` alone — never the router, `route-link.ts` or `detect.ts` (its links arrive as a prop), and `../derive/live.ts` through one dynamic import, only; and `exhibits.ts`, `derivations.ts`, `json-setting.ts`, `absences.ts` and `live-solve.ts` import nothing (held by the maintenance suite). Never `generated/` and never `src/data/`: both files it exhibits reach it as emitted data (AD-17), published byte for byte by `scripts/exhibits.ts` at `/career.json` and `/layout.generated.json` and fetched at runtime. Reaches `src/derive/` **only** through the one dynamic import of `live.ts` for the live re-solve (5.5) — never a static import, which would hoist the solver onto the entry path — and nothing outside `colophon.tsx` names `derive/live` (held by the maintenance suite).
**Imported by:** `src/shell/` via dynamic import only.
