# src/render-fallback/

The no-WebGL surface: the flat star chart (4.3), semantic DOM and an `aria-hidden` SVG plate, no Three and no canvas. Content parity with the scene is absolute — the artifact payload carries every field this surface renders, because the Fallback admits no truncation. It consumes the same artifact as the scene, which is what keeps the two from ever disagreeing about the data.

**Imports:** `src/shell/` (`panel-model.ts`, `chrome-model.ts`, and the stylesheet `focus-panel.css`) and `src/tokens/` — the artifact arrives only as the props `App` passes, never by importing `generated/layout.generated.json`. Never `src/data/`, never `src/derive/`, never `src/render-scene/` (dynamically or not), and never Three — neither `three` nor `@react-three/fiber` or `@react-three/drei`, which pull it in.
**Imported by:** `src/shell/fallback-host.tsx`, via dynamic import only.

## Files

| File | Role |
| --- | --- |
| `chart-model.ts` | The chart as a pure model. `buildChart(artifact)` → both plates, the index rows and the Client sections of records, present to past (`timeAxis` descending, ties by ID ascending). `acrossPlate` (desktop: one row per Client, `x = past − t·(past − present)` with present on the left, the Star `starOffset` left of its newest marker, the baseline from the Star to the oldest marker, Project labels on leaders alternating two depths) and `downPlate` (phone: the same chart transposed, Client stems stacked, labels wrapped to the plate's width). Each record is `buildPanel(artifact, id).blocks` minus the release button — the scene panel's kicker, title, reading position, field table and Skills — plus the dates as authored. `fragmentTarget(hash, ids)` → the entity a fragment names, or `null` (a decode error reads as no target); `landOnFragment(root, hash, ids, lookup, landed)` → the landing itself, with the browser injected: an attached root not yet in `landed` is marked, and the fragment's target, when the lookup finds it, is scrolled into view. `CHART_LABELS` — `Client`, `Project`, `Dates` — the chart's only new copy. Label widths are estimated from the type tokens, never measured. Reads `timeAxis` and nothing else from the solve. |
| `chart-model.test.ts` | Every model row of 4.3's I/O matrix — order with ties, parity against the committed artifact (each record's blocks hold every content value, Notable runs re-joined equal the authored prose minus its marks), the Shallow rule line string-equal to `EDITORIAL_RULE`, both plates' geometry (x strictly decreasing in `timeAxis`, everything inside the viewBox, the Star offset from its newest marker, alternating label levels; y increasing down each stem, Client blocks in order, marks a marker diameter apart; one baseline per Client across and one stem per Client down; no two label boxes intersecting on either plate), the fragment target and the landing (a Project or Client scrolled once, anything else and a detached ref scrolling nothing, a re-attached root not scrolling again) — and two scans driven over mutations: the directory's purity (no solve field, no `src/data`/`derive`/`render-scene`/`colophon`/`react-dom`/Three/artifact specifier, no canvas) and `chart.tsx`'s thinness (no `.sort(`, `.filter(`, `if (`, `?`, `&&`, `||`; the `switch` on a block's kind is the mapping and is allowed). |
| `chart.tsx` | The thin renderer, `default` export `Chart({ artifact })`: `<h1>` (`IDENTITY_LINE`), the two plates (one `aria-hidden` wrapper each around an SVG whose every colour and stroke is `chart.css`'s), the index table (Client, Project as a link to `#<id>`, Role, Dates), then a `<section id={client.id}>` per Client (`<h2>`) of `<article id={project.id}>` records (`<h3>` title) in the scene panel's markup and classes. Dates are `start`, ` – `, `end` as two elements, so an ongoing end draws nothing. The fragment is honoured once, on attach, by a ref callback that is one call to `landOnFragment` — no import from `react`, so the chunk does not depend on the mount's. |
| `chart.css` | The treatment, all from token custom properties: the page's ground, `surface-edge` plate frame, hairline baselines and leaders at `stroke-rest`, Stars at `stroke-active`, markers at `stroke-near` (one size, one ink), labels in the scene-label roles (`fill` at `ink-lift` / `ink-prose`), the index in the field roles, records on `surface-raised` with one `surface-edge` left rule. One query decides the swap: the down plate is `display: none` by default; at 640px and below the across plate is instead, the index rows stack (header clipped, not removed) and the record's field rows stack. Held, declaration by declaration, by `src/identity-audit.test.ts`. |

## Time is the axis

The plate reads one value from the solve, `timeAxis`, and nothing else: no 3D placement, no Body size or band, no Mote tier, no orbit. Those are the scene's projection; the chart is the career's. Every Project marker is drawn at one size and one ink — the Deep/Shallow signal on a flat chart (the ring) is story 4.4, and year marks belong to 4.5's date navigation.

## Why the chart is alone on its surface

`App` renders `fallback-host.tsx` alone on the `fallback` surface. The DOM destination index's buttons are scene doors (fly, pull back, focus a panel), and the corner chrome and the Focus panel are scene chrome; on the chart, the index table and the record anchors are the destination index, and none of it is canvas-backed. The page scrolls natively: `src/shell/page.css` locks scrolling only while the scene host is in the document.
